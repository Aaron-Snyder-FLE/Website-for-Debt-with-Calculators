# Project Instructions

These instructions apply to every page created or edited in this repository.

## Location and structure

- Save new pages in this repository unless the user specifies a subfolder.
- Keep the project as portable static HTML, CSS, and JavaScript suitable for GitHub Pages.
- Put image assets in `assets/` with clear, reusable filenames.
- Do not alter existing modules unless the user asks for those changes.

## Content fidelity

- Preserve the user's supplied wording, examples, order, and instructional structure.
- Do not condense, rewrite, invent headlines, or add new teaching claims without approval.
- Treat recurring examples and stories as intentional pacing devices. Keep them between their original vocabulary groups.
- If content is unclear or appears incomplete, retain it and flag it rather than silently replacing it.

## Visual direction

- Use a simple module title/header based on the supplied content. Do not invent a promotional hero headline.
- Keep related vocabulary together in clear visual groups.
- Avoid large walls of text. Pull out only meaningful concepts, decisions, formulas, or outcomes into restrained callouts.
- Do not put every paragraph in a box; retain ordinary narrative between highlights.
- Favor a calm, readable layout over decorative clutter.
- Ensure the page works without horizontal overflow on desktop and mobile.

## Interaction and accessibility

- Vocabulary cards should be accessible flip cards when requested: tap/click and Enter/Space must reveal the definition.
- Flip-card controls must expose useful labels and expanded state to screen readers, move focus appropriately, and include a way to return to the term.
- Drag-and-drop activities must also work by selecting/tapping a term and then its match.
- All interactive controls must be keyboard accessible and have visible focus states.
- Use semantic headings, descriptive image alt text, live feedback for activities, and reduced-motion support.

## Links and embeds

- Add external resource links only when the user supplies them or they are verified.
- Never style placeholder text as a clickable link. Remove dead, empty, or `#` links unless JavaScript replaces them with a valid destination at runtime.
- Open supporting resources in a new tab; navigation/return buttons may use the current tab.
- Microsoft Forms embeds must include a visible new-tab fallback link.

## Quality checks

- Preserve the original educational content while improving presentation.
- Test JavaScript syntax and core interactions after changes.
- Verify desktop and mobile layouts for overflow.
- Check touch, keyboard, and screen-reader interaction patterns.
- Confirm that local assets load and supplied URLs are wired to the intended labels.
